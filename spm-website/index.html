Project Charter — ChainID Blockchain Identity Management

Approved charter defining project authority, objectives, stakeholders, constraints, and how blockchain was engineered using SPM methodology.

Formal Project Charter
Charter Section Project Charter Details
Project Title & Code ChainID: Blockchain-Based Identity Management for Degree Verification (Topic 22)
Project Sponsor & Lead Sponsor: Faculty Guide, Chanakya University | Project Lead & Developer: Chukki (CU23BCA0019A)
Business Problem & Need Traditional verification requires graduates to share their entire academic record (CGPA, DOB, address) just to prove degree completion, risking privacy breaches, while physical/PDF credentials are easily forged.
Project Objectives & Success Criteria 1. Implement selective disclosure so candidates reveal only requested facts (e.g. Degree name + verified photo).
2. Anchor only a 32-byte Merkle root on the blockchain—zero personal data or grades stored on-chain.
3. Achieve 100% detection of tampered credentials in under 50ms verification latency.
Key Stakeholders • University (Issuer): Issues credentials & anchors Merkle root.
• Student (Holder): Holds private keys locally in browser wallet & creates proofs.
• Employer (Verifier): Sends one-time challenge nonce & runs 6 automated checks.
• Public / Consortium Ledger: Immutable audit trail of issued/revoked roots.
Timeline & Budget Baseline Duration: 28 Working Days (224 Hours) | Baseline Effort: 26 Person-Days (208 Hours) | Budget at Completion (BAC): ₹39,000 planned → ₹42,000 actual (28 PD @ ₹1,500/day).
Project Constraints & Risks Constraints: Hard 1-month timeline, zero gas bloat on-chain, browser-native crypto (no external wallet extension).
Primary Risk: Browser WebCrypto P-256 raw signature mismatch with Python ASN.1 DER (mitigated via converter bridge).

Materialized & Prevented Risks

Identified Risks & Response Actions

  • R1[Materialized] WebCrypto vs Python Signature Mismatch: Browser r||s signatures failed in Python.
    Action: Built ASN.1 DER converter in crypto_utils.py.
  • R2[Materialized] Student Photo Size Overflow: Base64 photos exceeded the 200-char cap.
    Action: Added 160×160 Canvas JPEG compression (~10 KB) + regex check.
  • R3[Materialized] Ganache Not Installed on Demo PC:
    Action: Built automatic LocalLedger hash-chain fallback so it works anywhere.
  • R4[Prevented] Replay & Dictionary Attacks:
    Action: Blocked via one-time 600s challenge nonces and 128-bit per-attribute salts.
Positive Risks

Opportunities Turned into Benefit

  • ★1. Browser-Native WebCrypto API (crypto.subtle):
    Instead of forcing students to install MetaMask, we used built-in browser P-256 cryptography—achieving 1-click wallet creation and JSON key backup.
  • ★2. AI APIs for SPM & Security Testing:
    Used AI tools to generate the Charter, Risk matrix, and 27 automated security assertions (pytest + e2e_check.mjs), saving ~4 person-days.
  • ★3. Interactive Visual Photo Verification:
    Turning the Student Photo into a Merkle leaf let us prove photo authenticity cryptographically without storing any image on the blockchain.
